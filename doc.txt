INSURANCE ETL PIPELINE

Project Description

The Insurance ETL Pipeline is an end-to-end data engineering project that processes insurance policy, claims, premium, and risk data.

The project uses Python, Apache Kafka, PySpark, MySQL or Amazon RDS, Amazon S3, AWS Lambda, and AWS Step Functions.

The pipeline performs data ingestion, transformation, validation, calculation, aggregation, and storage.

STEP 9: PREMIUM ETL PROCESSING

Run the premium ETL script:

python3 databricks/insurance_etl.py

Premium calculation rules:

1. Base Premium is equal to Annual_Premium.

2. If Age is greater than 60, add 15 percent to the premium.

3. If Vehicle_Age is greater than 2 years, add 10 percent to the premium.

4. If Vehicle_Damage is Yes, add 8 percent to the premium.

5. If Previously_Insured is 0, add 5 percent to the premium.

Final Premium Formula:

Final_Premium = Base_Premium + Applicable Premium Increases

Premium status rule:

If Final_Premium is greater than 60000, Premium_Status is High.

Otherwise, Premium_Status is Normal.

Premium output columns:

id
Base_Premium
Final_Premium
Premium_Status

STEP 13: CLAIMS ETL PROCESSING

Run:

python3 databricks/claims_etl.py

Claims processing steps:

1. Merge claims files from different cities.
2. Remove duplicate records.
3. Validate customer IDs against policy IDs.
4. Remove claims belonging to invalid customer IDs.
5. Aggregate the total claim amount for each customer.

Claims output columns:

customer_id
Total_Claim_Amount


STEP 14: RISK ETL PROCESSING

Run:

python3 databricks/risk_etl.py

Risk score calculation rules:

1. If Age is greater than 60, add 30 points.

2. If Vehicle_Age is greater than 2 years, add 20 points.

3. If Vehicle_Damage is Yes, add 25 points.

4. If Previously_Insured is 0, add 15 points.

5. If Annual_Premium is greater than 50000, add 10 points.

Risk level rules:

Risk score from 0 to 30: Low

Risk score from 31 to 60: Medium

Risk score greater than 60: High

Risk output columns:

id
Risk_Score
Risk_Level


STEP 15: LOAD DATA INTO MYSQL OR AMAZON RDS

Create the database:

CREATE DATABASE insurance_db;

Use the database:

USE insurance_db;

Create the premium table:

CREATE TABLE premium (
    id INT PRIMARY KEY,
    Base_Premium DECIMAL(12,2),
    Final_Premium DECIMAL(12,2),
    Premium_Status VARCHAR(20)
);

Create the claims table:

CREATE TABLE claims (
    customer_id INT PRIMARY KEY,
    Total_Claim_Amount DECIMAL(12,2)
);

Create the risk table:

CREATE TABLE risk (
    id INT PRIMARY KEY,
    Risk_Score INT,
    Risk_Level VARCHAR(20)
);

Update the .env file with the local MySQL or Amazon RDS connection details.

Run the database loader:

python3 database_loader.py

The loader inserts the processed premium, claims, and risk records into the database tables.


STEP 16: AMAZON S3 STORAGE

Amazon S3 can be used to store raw, processed, and archived data.

Suggested S3 structure:

s3://insurance-etl-bucket/raw/

s3://insurance-etl-bucket/processed/

s3://insurance-etl-bucket/archive/

Raw data is stored in the raw folder.

Processed ETL results are stored in the processed folder.

Old or completed files are stored in the archive folder.


STEP 17: AWS LAMBDA

AWS Lambda can be used for serverless processing.

Possible Lambda responsibilities:

1. Validate uploaded files.
2. Trigger ETL processing.
3. Move files from raw to processed.
4. Archive completed files.
5. Update processing status.
6. Send notifications after completion.

The Lambda function used during the project is:

student-data-processor


STEP 18: AWS STEP FUNCTIONS

AWS Step Functions can orchestrate the ETL workflow.

Possible workflow:

1. Validate input file.
2. Start processing.
3. Process premium data.
4. Process claims data.
5. Calculate risk.
6. Store results.
7. Archive input data.
8. Send completion notification.

Step Functions coordinates the execution of multiple Lambda functions in a defined order.
